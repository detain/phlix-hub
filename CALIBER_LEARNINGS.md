# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `./vendor/bin/psalm` cannot run on this dev box: it fails the platform check `Psalm requires a PHP version ">= 8.3.16". You are running 8.3.6.` and exits without analyzing. Verify with phpstan + phpcs locally and rely on the CI Psalm job; read the actual Psalm failure from `gh run view --job <id> --log`.
- **[fix]** To simulate the CI environment (swoole NOT loaded) locally for PHPStan, do NOT use `php -n` — it strips json and breaks the phar (`Class "Phar" not found`). Instead symlink every `/etc/php/8.3/cli/conf.d/*.ini` EXCEPT the swoole one into a temp dir and run with `PHP_INI_SCAN_DIR=$TMPINI php vendor/bin/phpstan analyze ...`; confirm with `PHP_INI_SCAN_DIR=$TMPINI php -m | grep -i swoole`.
- **[gotcha]** PHPStan (no swoole, sees `mixed`) and CI Psalm (swoole loaded, sees real types) give OPPOSITE verdicts on the SAME guard. `Swoole\Coroutine::getCid()`: PHPStan REQUIRES an `is_int()` guard, Psalm flags it `RedundantCondition`. `$this->pdo instanceof \PDO`: PHPStan needs the guard to call `setAttribute()` safely, Psalm flags it `RedundantConditionGivenDocblockType` (parent types `$pdo` as `\PDO`). Keep the guard for PHPStan and add a `@psalm-suppress RedundantCondition,TypeDoesNotContainType,RedundantConditionGivenDocblockType` PHPDoc — do NOT drop the guard.
- **[fix]** `Call to a member function bindParam() on false` / `HY093 Invalid parameter number` from `workerman/mysql` under concurrent Swoole requests is CONNECTION CORRUPTION, not a binding bug. The per-coroutine query mutex does NOT fix it. The fix: override `connect()` to set `PDO::ATTR_EMULATE_PREPARES = true` + `PDO::MYSQL_ATTR_USE_BUFFERED_QUERY = true`. Native unbuffered prepares keep per-statement state on the coroutine-hooked mysqlnd socket that leaks across coroutine yields and wedges the shared connection.
- **[gotcha]** Both PDO attributes are required for the workerman/mysql coroutine-corruption fix: a buffered-only override (`MYSQL_ATTR_USE_BUFFERED_QUERY` WITHOUT `ATTR_EMULATE_PREPARES`) still produced ~2% 500s in a live concurrent burst. You need emulated prepares too — buffered alone is not sufficient.
- **[gotcha]** Turning on `PDO::ATTR_EMULATE_PREPARES` in `PhlixMySQLConnection` makes PDO send EVERY bound param as a STRING by default, so `LIMIT :limit` / `OFFSET :offset` become `LIMIT '50'` and MySQL rejects them with a 1064 syntax error (breaks `HeartbeatHandler` recent-server lookup and any paginated query). Fix: override `execute()` to `bindValue()` each param with its natural PDO type (`int → PARAM_INT`, `bool → PARAM_BOOL`, `null → PARAM_NULL`, else `PARAM_STR`) so integer placeholders stay unquoted. Mirror the parent's prepare/execute + one-shot 2006/2013 reconnect.
- **[gotcha]** When overriding `connect()` or `execute()` from `Workerman\MySQL\Connection`, the parent declares them WITHOUT a return type — do NOT add `: void` (signature-compat mismatch at runtime); satisfy PHPStan with a `@return void` PHPDoc instead. The parent's `clearSQuery()` is `private` — inline its one line (`$this->sQuery = null`) rather than calling it; `$sQuery`/`$success`/`$pdo` are `protected` and reusable.
- **[pattern]** Measure DB-corruption fixes on the live hub with a before/after log delta, not HTTP-code histograms: `grep -cE 'bindParam|HY093|on false|Invalid parameter|1064|syntax'` on `.logs/app-<date>.log` before and after a concurrent `curl` burst (e.g. 10 rounds × 12–15 parallel POSTs with unique keys). A `200`-only histogram hides duplicate-key vs socket-corruption 500s — the log delta of 0 is the real pass signal.
- **[pattern]** Live-debug the deployed hub by patching `/opt/phlix-hub/src/...` in place, `php -l`, `systemctl restart phlix-hub`, fire a concurrent `curl` burst, then `cd /opt/phlix-hub && git checkout -- <file>` to restore. Use a NON-perturbing in-flight counter (increment after lock acquire, log only if >1) to detect query overlap — `file_put_contents` instrumentation MASKS the race because file I/O yields the coroutine.
- **[gotcha]** Overly nested bash/python heredocs over SSH (multiple layers of `\\$` and quote escaping) silently fail and return EMPTY output. When a heredoc patch returns nothing, compute the volatile value separately and apply it with a simple `sed`, or base64-pipe the whole file (see the single-file-deploy pattern) rather than escalating the escaping.
- **[gotcha]** `Swoole\Coroutine::getCid()` triggers OPPOSITE complaints from the two static analysers: Psalm (CI loads ext-swoole, reflects the real `int` return) flags an `is_int($cid)` guard as `RedundantCondition`/`TypeDoesNotContainType`, while PHPStan (runs WITHOUT swoole, sees `mixed`) REQUIRES that same guard to narrow the return or errors `return.type`. Keep the `is_int()` guard for PHPStan and add `@psalm-suppress RedundantCondition,TypeDoesNotContainType` on the method — do NOT drop the guard to satisfy Psalm. - **[gotcha]** Both the HS256 JWT secret AND the DB credentials live ONLY in the systemd `EnvironmentFile` (`/etc/phlix-hub.env`). Any standalone `php` CLI script on the live box dies with 1045 `Access denied for user 'phlix_hub'` (DB) or signs JWTs with the wrong secret (→ 401 `auth.invalid_token`). Source it first: `ENVF=$(systemctl cat phlix-hub | grep -oE 'EnvironmentFile=-?[^ ]+' | head -1 | sed 's/EnvironmentFile=-\?//'); set -a; . "$ENVF"; set +a; php /tmp/script.php`.
- **[pattern]** Deploy to the live box over SSH with `ssh root@<host> 'sudo bash /opt/phlix-hub/scripts/install.sh --update -y'` — phlix-hub lives at `/opt/phlix-hub`, phlix-server at `/var/www/phlix`. `--update` pulls, runs idempotent migrations ("Duplicate column"/"Duplicate key name" notes are benign), restarts the service, and runs a health check.
- **[gotcha]** A background `until [ pending=0 ]; do sleep; done` CI poller can leave its `.output` task file EMPTY for a long time (the loop never reaches the final echo while checks are queued). Don't keep re-Reading the empty file — poll the PR directly with `gh pr checks N` or a bounded `for n in 1..8; do ...; sleep 15; done` loop.
- **[pattern]** Run `unset GITHUB_TOKEN GH_TOKEN` before `git push`/`gh` in this workspace — pushes use the SSH remote (`git@github.com:detain/...`) and a stale token in the env can interfere.
